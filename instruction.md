# Prompt: Build an AI-Powered RCA Agent for Docker Containers

## Objective

Build an enterprise-grade AI Root Cause Analysis (RCA) Agent that continuously monitors Docker container logs, detects errors in real time, analyses the root cause using AI, suggests possible solutions, and automatically notifies DevOps teams through Google Chat and Email.

The solution should be modular, scalable, secure, and production-ready.

# Core Features

The agent should continuously monitor all running Docker containers.

It should

* Auto discover new containers.
* Start monitoring newly created containers automatically.
* Stop monitoring deleted containers.
* Read logs in streaming mode.
* Support both stdout/stderr.
* Support json-file logging driver.
* Support journald.
* Support syslog.

No container restart should be required.

# Security Best Practices

* Never expose `/var/run/docker.sock` externally.
* Run the agent as a non-root user whenever possible. If Docker socket access requires elevated group permissions, grant only the minimum required access.
* Store API keys, SMTP credentials, and webhook URLs in Docker Secrets or a secure secrets manager rather than hardcoding them.
* Encrypt all communication with external services using HTTPS/TLS.
* Implement RBAC for the dashboard and APIs.
* Mask sensitive information such as passwords, tokens, JWTs, API keys, and PII before sending logs to AI models or notifications.
* Encrypt PostgreSQL data at rest where supported and enable regular backups.
* Audit all AI-generated RCA reports and user actions for traceability.
* Apply rate limiting to notification channels to prevent alert storms.

# Production Deployment Steps

1. Deploy PostgreSQL and Redis.
2. Deploy the AI RCA Agent as a dedicated Docker container.
3. Mount the Docker socket (`/var/run/docker.sock`) into the agent container with read-only access where feasible.
4. Configure Google Chat webhook, SMTP settings, and AI provider credentials.
5. Verify the agent can discover and monitor all running containers.
6. Generate test errors to validate log ingestion and AI analysis.
7. Configure Nginx as a reverse proxy for the dashboard with HTTPS.
8. Enable custom log file monitoring (`CUSTOM_LOG_FILES`) for applications that run outside Docker.
9. Configure log rotation, retention policies, and automated database backups.
10. Set up health checks and automatic restart policies for all services.
